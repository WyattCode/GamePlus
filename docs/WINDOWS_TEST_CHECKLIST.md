# Game+ Windows 手动测试清单

本清单用于每个版本发布前在真实 Windows 机器上做人工验证。所有条目均为 `- [ ]` 复选框，格式为
「操作 → 预期结果」。技术名词（UAC、SmartScreen、schtasks、netsh、WinTUN、netfilter 等）保留英文。

测试时请尽量使用**干净的系统快照**，并在开始前记录下面的环境信息。

## 测试环境记录

- [ ] 记录 Windows 版本与内部版本号（`winver` 或 `Get-ComputerInfo | Select OsName,OsVersion,OsBuildNumber`）→ 已填写到下方表格，且为 Windows 10 build 17763+ 或 Windows 11
- [ ] 记录系统架构（`$env:PROCESSOR_ARCHITECTURE`）→ 为 `AMD64`（x64）
- [ ] 记录安装/运行账户类型（管理员账户 / 标准用户账户）→ 已填写，且明确本次测试使用的是哪一种
- [ ] 记录杀毒软件/安全软件名称与版本（Windows Defender 或第三方）→ 已填写，且实时防护处于开启状态
- [ ] 记录网络环境（家用宽带 / 公司网络 / 移动热点，是否有代理或 VPN）→ 已填写
- [ ] 记录 Game+ 版本号（设置 → 关于，或安装包文件名）→ 已填写
- [ ] 记录安装路径（默认 `C:\Program Files\Game+`）→ 已填写
- [ ] 记录测试用游戏名称与平台（Steam / Epic / 其他）→ 已填写

## 全新安装

- [ ] 在从未安装过 Game+ 的机器上双击 `Game+-x.y.z-x64.exe` → 出现 UAC 提示，确认后进入 NSIS 安装向导
- [ ] 安装向导默认目录 → 显示为 `C:\Program Files\Game+`
- [ ] 完成安装 → 安装结束时无报错，`C:\Program Files\Game+` 下存在 `Game+.exe` 与后端 `gameplus-host.exe`
- [ ] 检查安装目录 ACL（`icacls "C:\Program Files\Game+"`）→ 普通用户（Users）只有读取/执行权限，没有写入权限
- [ ] 检查开始菜单与桌面快捷方式 → 快捷方式存在且指向 `C:\Program Files\Game+\Game+.exe`
- [ ] 首次启动 Game+ → 主界面正常显示，无白屏、无未捕获异常弹窗
- [ ] 检查「控制面板 → 程序和功能」→ 存在 Game+ 条目，发布者为安装包信息中的发布者
- [ ] 检查计划任务（`schtasks /Query /TN "\Game+\AutoStart"`）→ 全新安装后默认**不存在**该任务（开机启动默认关闭）
- [ ] 打开 设置 → 开机启动 开关 → 开关可用（未被禁用），并显示说明文字
- [ ] 检查 `%AppData%\Game+` 与 Electron userData 目录 → 首次启动后目录被创建，且不包含任何上传队列/账号信息

## 从旧版按用户安装升级

> 前置：先安装旧版本（按用户安装到 `%LOCALAPPDATA%\Programs\Game+`），并开启其开机启动。

- [ ] 在旧版已安装且开机启动已开启的机器上运行新版安装包 → 安装向导正常启动，无「已安装」冲突报错
- [ ] 安装完成后检查 `%LOCALAPPDATA%\Programs\Game+` → 旧目录已被卸载程序删除（不存在或为空）
- [ ] 检查旧版自动启动任务（`schtasks /Query /TN "\Game+\AutoStart"`）→ 旧任务已被删除；若新版尚未开启开机启动，则查询返回「找不到」类错误
- [ ] 检查「控制面板 → 程序和功能」→ 只有一条 Game+ 记录，且指向新版本
- [ ] 启动新版 → 版本号为新版本，设置项（订阅/规则等）按预期保留或按迁移策略处理，无崩溃
- [ ] 打开 设置 → 开机启动 → 开关处于关闭状态，并提示需要重新开启
- [ ] 手动开启开机启动 → 开关变为开启，`schtasks /Query /TN "\Game+\AutoStart"` 能查到任务
- [ ] 注销并重新登录 → Game+ 自动启动且无 UAC 提示（详见「开机启动」章节）
- [ ] 检查旧版遗留的 `%LOCALAPPDATA%\Programs\Game+` 中的用户数据 → 未被误删（如订阅、配置），或按文档说明已迁移

## UAC 与 SmartScreen

- [ ] 在未签名的安装包上双击运行 → SmartScreen 显示「Windows 已保护你的电脑」
- [ ] 点击「更多信息」→ 出现「仍要运行」按钮
- [ ] 点击「仍要运行」→ 安装向导正常启动，随后出现一次 UAC 提权提示
- [ ] 在 UAC 提示中点击「否」→ 安装中止，系统无残留文件、无残留计划任务
- [ ] 安装完成后以标准用户账户启动 Game+ → 主界面可正常打开（不需要管理员权限即可查看界面）
- [ ] 在标准用户账户下开启需要提权的功能（如 TUN 模式 / 开机启动）→ 出现 UAC 提示或给出明确的权限不足说明，不静默失败
- [ ] 校验安装包 SHA-256（`certutil -hashfile "Game+-x.y.z-x64.exe" SHA256`）→ 与发布页给出的值一致
- [ ] 检查杀毒软件日志 → 若报毒，记录具体文件名与报毒名称（netfilter / WinTUN 驱动可能被误报），并确认可加入白名单后正常使用

## 加速 / 停止

> 每个模式（进程模式 / TUN 模式 / 系统代理）分别执行以下条目。

- [ ] 选择「进程模式（netfilter 驱动）」并点击「加速」→ 状态变为已加速，界面显示当前模式与生效的进程
- [ ] 加速后检查驱动状态（`sc query` 或设备管理器中的 netfilter 相关服务）→ 驱动已加载/服务处于运行状态
- [ ] 在游戏中确认网络可用（登录、进入对局）→ 游戏可正常联网，延迟符合预期
- [ ] 点击「停止」→ 状态回到未加速，界面无残留「加速中」提示
- [ ] 停止后检查系统代理（`netsh winhttp show proxy` 与「Internet 选项 → 连接 → 局域网设置」）→ 系统代理已恢复为加速前的状态（通常为「直接访问/无代理」）
- [ ] 停止后检查路由表（`route print`）→ 加速期间新增的路由条目已被移除，默认路由未被篡改
- [ ] 停止后检查 DNS 设置（`netsh interface ip show dns`）→ 各网卡 DNS 恢复为加速前的值
- [ ] 选择「TUN 模式（WinTUN）」并点击「加速」→ 状态变为已加速，网络适配器中新增 WinTUN 虚拟网卡
- [ ] TUN 模式下确认游戏可联网 → 游戏可正常登录与对局
- [ ] TUN 模式点击「停止」→ WinTUN 适配器被移除或禁用，路由表恢复，网络恢复正常
- [ ] 选择「系统代理」并点击「加速」→ 系统代理被设置为本地监听地址（`netsh winhttp show proxy` 可见）
- [ ] 系统代理模式下确认浏览器/游戏可联网 → 流量按预期走代理
- [ ] 系统代理模式点击「停止」→ 系统代理恢复为加速前的值
- [ ] 加速过程中用任务管理器强制结束 `gameplus-host.exe` → 前端检测到后端退出，界面提示异常并回到未加速状态
- [ ] 后端被强杀后检查系统代理与路由 → 系统代理已恢复、路由条目已清理（无「断网」残留）
- [ ] 后端被强杀后重新启动 Game+ → 可正常再次加速，无「端口被占用」「驱动已加载」类错误
- [ ] 加速过程中直接关闭 Game+ 主窗口（退出程序）→ 后端随之退出，系统代理/路由/WinTUN 状态全部恢复
- [ ] 加速过程中重启系统 → 重启后系统代理与路由为正常状态，Game+ 未处于「假加速」状态

## 国服/国际服切换

- [ ] 打开某个游戏的加速设置 → 默认选中「国际服」
- [ ] 选择「国际服」并加速 → 使用的节点均为海外节点，界面/日志中不出现国内线路
- [ ] 在「国际服」下人为构造「无可用海外节点」的情况（如把订阅节点全部禁用）→ 程序给出明确提示，并按规则回退（仅在无海外节点可用时才允许使用国内线路），不静默切换
- [ ] 选择「国服」并加速 → 使用国内线路，延迟明显低于国际服
- [ ] 在国服/国际服之间反复切换并各加速一次 → 每次切换后实际生效的线路与选择一致，界面显示与日志一致
- [ ] 关闭并重新打开 Game+ → 上次选择的国服/国际服状态被正确保留
- [ ] 对同一游戏分别用国服与国际服加速 → 加速效果卡片中的延迟数据随线路变化，且与所选线路相符

## 智能选线

- [ ] 点击「智能选线」/ 启动加速 → 程序自动选择节点，并显示选择**理由**（如「延迟最低」「丢包最低」「同区域」）
- [ ] 查看选线理由 → 理由文本具体、可理解，不是空白或占位符
- [ ] 手动指定一个节点后再点击智能选线 → 重新按智能策略选择，并更新理由
- [ ] 在智能选线过程中断开网络 → 给出明确的失败提示与原因，不卡死、不无限转圈
- [ ] 恢复网络后再次智能选线 → 可正常选出节点并加速成功
- [ ] 连续多次智能选线 → 结果稳定（同一网络条件下不会在明显更差的节点间随机跳变），且每次都有理由
- [ ] 查看本地诊断记录 → 记录了本次选线结果与理由（已去除 IP/域名/路径/用户名）

## 直连基线与加速效果卡片

- [ ] 首次对某个游戏点击加速 → 自动测量一次直连基线（TLS handshake 延迟），卡片显示「加速效果（参考）」
- [ ] 加速效果卡片内容 → 显示直连基线与加速后延迟的对比，并标注为「参考」
- [ ] 停止后再次加速同一游戏 → 复用首次测得的基线，不重复测量（可通过耗时或日志确认）
- [ ] 点击卡片上的「重新测量」→ 重新测量直连基线并刷新卡片数值
- [ ] 打开 高级设置 → 存在「每次加速前测量直连基线」开关
- [ ] 开启「每次加速前测量直连基线」后加速 → 每次加速都会重新测量基线，卡片数值随之更新
- [ ] 关闭该开关后加速 → 恢复为复用首次基线的行为
- [ ] 在直连基线测量过程中断网 → 卡片给出「测量失败/不可用」的明确状态，不影响加速本身
- [ ] 对第二个游戏首次加速 → 该游戏独立测量并保存自己的基线，与第一个游戏互不影响

- [ ] 对需要管理员权限的修复项（如驱动/路由）在标准用户下点击 → 出现 UAC 提示或明确说明需要管理员权限，不静默失败
- [ ] 一键修复过程中断网 → 给出明确失败原因，界面不卡死
- [ ] 修复完成后点击「加速」→ 可正常加速，说明修复确实生效
- [ ] 诊断对话框中的「导出诊断包」→ 生成文件成功，且内容中不含订阅 URL、密码等敏感信息（如含，需在分享前手动删除）

- [ ] 已安装 Steam 游戏 → 被正确识别并列出（名称、平台、安装路径）

- [ ] 其他支持的平台（如已安装）→ 被正确识别

## 自动加速

- [ ] 在游戏设置中开启「自动加速」→ 开关状态被保存
- [ ] 启动对应游戏进程 → Game+ 自动开始加速，界面/托盘提示已自动加速
- [ ] 自动加速后关闭游戏 → 按设计自动停止加速（或保持，需与文档一致），系统代理/路由恢复
- [ ] 启动一个未配置自动加速的游戏 → 不会触发自动加速
- [ ] 在 Game+ 未运行（已退出）时启动游戏 → 不会自动加速（或按设计由托盘常驻触发，需与文档一致）
- [ ] 关闭「自动加速」后再启动游戏 → 不再自动加速
- [ ] 自动加速失败（如节点不可用）→ 给出明确提示与原因，不静默失败

## 托盘

- [ ] 点击托盘「显示主界面」→ 主窗口显示并置前
- [ ] 关闭主窗口（点 X）→ 程序最小化到托盘而非退出（按设计），托盘图标仍在
- [ ] 通过托盘菜单「退出」→ 程序完全退出，后端进程结束，系统代理/路由恢复
- [ ] 开启「启动时最小化到托盘」后重启 Game+ → 启动后不显示主窗口，仅托盘图标存在
- [ ] 托盘图标在加速中/未加速状态 → 图标或提示文字能区分状态
- [ ] 在托盘菜单中直接加速/停止 → 状态与主界面同步

## 开机启动

- [ ] 在 `C:\Program Files\Game+` 安装且以管理员完成安装后，打开 设置 → 开机启动 → 开关可用
- [ ] 开启开机启动 → `schtasks /Query /TN "\Game+\AutoStart"` 能查到任务
- [ ] 查看任务 XML（`schtasks /Query /TN "\Game+\AutoStart" /XML`）→ 运行级别为「最高权限」（RunLevel = HighestAvailable），触发方式为登录时（At log on），操作为 `Game+.exe` 且带 `--hidden` 参数，路径指向 `C:\Program Files\Game+\Game+.exe`
- [ ] 注销并重新登录 → Game+ 自动启动，**不出现 UAC 提示**（因为任务以最高权限运行）
- [ ] 登录后观察 → Game+ 以隐藏方式启动，仅托盘图标可见（`--hidden` 生效）
- [ ] 关闭开机启动 → `schtasks /Query /TN "\Game+\AutoStart"` 返回「找不到」类错误，任务已删除
- [ ] 把 Game+ 安装到 Program Files 之外的目录（如 `D:\Game+`）→ 设置 → 开机启动 开关被**禁用**，并显示原因说明
- [ ] 使用解压版/便携版运行（未经过安装程序）→ 开机启动 开关被禁用，并显示原因说明
- [ ] 用 `icacls "C:\Program Files\Game+" /grant Users:(M)` 放宽目录 ACL 后重启 Game+ → 开机启动 开关被禁用并显示原因（目录对普通用户可写）
- [ ] 恢复 ACL（`icacls "C:\Program Files\Game+" /remove:g Users` 或还原为仅管理员可写）后重启 → 开机启动 开关恢复可用
- [ ] 手动创建一个指向其他路径的 `\Game+\AutoStart` 任务（`schtasks /Create /TN "\Game+\AutoStart" /TR "C:\Temp\evil.exe" /SC ONLOGON /RL HIGHEST`）后启动 Game+ → 该任务在启动时被自动删除
- [ ] 手动创建一个指向用户可写路径的任务后启动 Game+ → 该任务被自动删除
- [ ] 卸载 Game+ → `\Game+\AutoStart` 任务被一并删除

- [ ] 在规则分流下访问国外站点/游戏 → 走代理

- [ ] 重启 Game+ → 分流设置被正确保留

## 软件更新

- [ ] 打开 设置 → 软件更新 → 默认状态下更新来源为空，功能处于关闭状态
- [ ] 填入一个有效的更新清单 URL（`{ "version", "url", "sha256", "notes" }`）→ 保存成功
- [ ] 点击「检查更新」→ 能读取清单并显示版本号与更新说明
- [ ] 清单中 `sha256` 缺失或格式错误 → 给出明确错误提示，不下载
- [ ] 有可用新版本时点击下载 → 下载完成后校验 sha256，校验通过才允许安装
- [ ] 人为篡改下载文件（使 sha256 不匹配）→ 校验失败并给出明确提示，拒绝安装
- [ ] 使用 GitHub Releases 作为更新来源 → 能正确列出并选择最新版本
- [ ] 更新来源 URL 不可访问 → 给出明确的网络错误提示，不卡死
- [ ] 更新过程中关闭 Game+ → 不产生损坏的安装包残留（或残留可被下次清理）

## 本地诊断记录与崩溃文件

- [ ] 打开 设置 → 本地诊断记录 → 能看到加速成功/失败、模式与失败原因等条目
- [ ] 检查记录内容 → 不含 IP、域名、路径、用户名等敏感信息
- [ ] 点击「清除」→ 记录被清空
- [ ] 关闭「本地诊断记录」开关后使用 → 不再新增记录
- [ ] 人为让后端崩溃（如任务管理器结束 `gameplus-host.exe` 并触发异常路径）→ `%AppData%\Game+\crashes` 下生成崩溃文件
- [ ] 人为让前端崩溃 → Electron userData 目录下的 `crashes` 文件夹生成崩溃文件
- [ ] 使用「资源监视器 → 网络」观察 Game+ 与 `gameplus-host.exe` 的联网行为 → 除代理/更新/规则库等用户配置的目标外，无向第三方上传诊断或崩溃数据的行为
- [ ] 用防火墙日志（`netsh advfirewall` 或第三方防火墙）记录出站连接 → 未发现上传崩溃/诊断数据的连接
- [ ] 断网状态下使用 Game+ 并触发崩溃 → 崩溃文件仍保存在本地，程序不因上传失败而卡顿或报错
- [ ] 检查 `%AppData%\Game+\crashes` 与 userData 下的 `crashes`、`telemetry` 目录 → 文件仅存在于本机，无上传队列/临时上传文件

## 卸载清理

- [ ] 通过「控制面板 → 程序和功能」卸载 Game+ → 出现 UAC 提示，确认后卸载完成
- [ ] 检查 `C:\Program Files\Game+` → 程序文件已被删除（或仅剩空目录）
- [ ] 检查 `schtasks /Query /TN "\Game+\AutoStart"` → 任务已被删除
- [ ] 检查系统代理（`netsh winhttp show proxy` 与 Internet 选项）→ 已恢复为未加速状态
- [ ] 检查路由表（`route print`）→ 无 Game+ 添加的残留路由
- [ ] 检查网络适配器 → WinTUN 虚拟适配器已被移除
- [ ] 检查 netfilter 驱动/服务状态（`sc query` 或设备管理器）→ 驱动已卸载或恢复为未加载状态
- [ ] 检查开始菜单/桌面快捷方式 → 已被删除
- [ ] 检查用户数据目录（`%AppData%\Game+`、Electron userData 目录）→ 按设计保留或删除，并在文档中注明位置；若保留，重新安装后能正确读取
- [ ] 卸载后重启系统 → 网络正常，无残留代理/路由/驱动导致断网
